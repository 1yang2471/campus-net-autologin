# 2026-11-10：流量用完后面板切账号无效

> 用户操作：旧账号（23jszeng）流量用完 → 面板设置切换账号到 23ykyang →
> 面板看似成功但网络仍不通 → 浏览器手动注销并登录新账号后恢复。本文是
> 只读诊断 + 修复记录。

## 0. 结论（一句话）

面板切账号**只注销 v6，不注销 v4**。v4 会话仍挂在旧账号（流量用完但未下线）
名下时，新账号登录被门户答「用户已在线，不需要再次认证」——判定器把它当成功
哨兵，归属却不改。手动浏览器「先注销再登录」补齐了缺失的 v4 注销，因此有效。

## 1. 现场证据

| 项 | 数据 |
|---|---|
| 配置 | 切换发生在 19:08（config.ini mtime），`username` 已写成 23ykyang |
| 状态日志 | 19:08–19:10 无切账号记录（结果只回面板，不落日志）；状态持续「在线／出口受限」抖动 |
| 门户只读探针 | 手动恢复后 `online_check` → `{"success":true,"online":1,"username":"23ykyang"}` |
| 账号历史 | `[accounts]` 23ykyang / 23jszeng（旧账号流量用完） |
| 门户族事实 | ac_portal 已在线应答「用户已在线，不需要再次认证」（`campus-portal-survey.md` §1）；keeper 判定器视为成功哨兵 |

## 2. 根因链

1. 旧账号流量用完但会话仍在线（v4 仍归旧账号）。
2. `switchAccount` 的释放步只调用 `logoutV6`；v4 从未注销。
3. 新登录发出后，门户按**地址**判「已在线」，返回成功哨兵；
   `JudgeLoginResponse` 判成功（这是防登录风暴的正确语义，不是 bug 本身）。
4. 归属核对以 v6 承重：v6 已注销/不可观测时，`ownerClause` 只说「v6 当前
   不在线」，**完全掩盖 v4 仍归旧账号**。
5. 面板因此显示接近成功；用户仍无网。浏览器注销 v4 后再登录，门户才改归属。

## 3. 修复

- 切账号释放步拆成 v4/v6 两路，顺序 **v6 → v4 → 认证**（v4 注销会短暂断数据，
  放最后少断网）。
- 新增 `logoutV4`：与门户自己的 logout 流程同形，纯 v4 表单不带 `ipv4or6`，
  服务端按请求源地址认栈；走双路径选路（TUN 下可回退系统栈）。
- `inspectStacks` 改成两侧独立读数：v4 承重、v6 补充；v6 不可观测不再掩盖 v4。
- 回报措辞：v4 仍归旧账号 / v4 不在线 / v4 不可读都明确说「切换未生效」，
  不再建议走不通的「立即检测重连」；双栈关时不报 v6 噪声。
- 切换结果写入状态日志（此前只在面板一闪而过，事故无现场）。
- 双栈关时不接管 v6 注销（v6 不归本次切换管）。

## 4. 验证

- 新增回归：假门户按地址归属记账（v4 在线 → 登录只答「已在线」；logout 才
  释放）。**去掉 v4 注销的变异立刻判红**（v4 仍归 old），恢复后全绿。
- 全量门：`go test ./... -count=1` / `go vet ./...` / Android 交叉编译全绿。
- **待真机复验**：用新构建在两账号间来回切一次，确认面板回报
  「门户确认 v4 已归 …」，且无需浏览器手动操作。

## 5. 边界

- v4 注销会让数据通道短暂中断（毫秒级到数秒），这是切账号的必要代价。
- 若新账号凭据已失效，v4 注销后认证会失败、用户会短暂离线；回报会明确提醒
  「旧 v4 会话已注销，当前可能离线——修正凭据后重试，或切回原账号」。
  旧行为虽不断网，但根本没切换成功。
- 若代理规则把校园域名判为走境外节点，门户看到的源地址不是校园 v4，注销会
  落空；这与登录本身同源，属代理拓扑问题，不是本次修复能覆盖的。
