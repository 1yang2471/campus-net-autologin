## 三个缺陷（代码级实锤，全部当日修复）

1. **锚点白名单假绿**：`probeAnchor` 带小米 Host（`egress.go`），校园把探测域名白名单放行
   （`detect.go` 2026-11-11 已实测），未认证拿 404 判「在线」。detect 层修过、运行时层漏改。
2. **熔断连坐**：SESSION_FALSE 熔断停了整个会话探针（含 IP 级 online_check）——真死无人报。
3. **哨兵清状态过快**：判死后重登答「已在线」直接点亮在线——账号级在线 ≠ 本 IP 会话恢复
   （账号绑别处时被拒绑仍报成功）。

## 三刀修复（全部失败测试先行→修复→全量门绿）

- 刀 1：probeAnchor 先不带 Host（对齐 probeHostVariants）；**同 IP 见劫持即终局**，不问第二变体。
- 刀 2：fluxOffUntil 只停 flux 回落，SessionAlive 不连坐；L2 受限持续 ≥10min 点名「持续」
  （可见性升级，不改判定）。
- 刀 3：哨兵命中当场用 SessionAlive 复核——报活（flux 撒谎型）回在线；报死（账号绑别处型）
  保持判死走 t37，suspect 熔断截断循环并点名「疑账号绑定在别处」。未接线保持 Python 原语义。
- 附：通道登录补事件日志（此前通道自愈在状态日志里无痕）。

测试：`TestProbeAnchorNotFooledByWhitelistedHost`、`TestFluxOffKeepsSessionAlive`、
`TestL2StreakShownAsPersistent`、`TestAlreadyOnlineVerifiedBySessionAlive`、
`TestAlreadyOnlineLoopCappedBySuspect`。构建 10:21:27 装机，守护 PID 38112 上线。

## M2-c 真机踢线验证（同日完成）与通道登录恒拒 bug

两轮踢线（绑 WiFi 源 172.29.153.208 向门户发 logout，门户回「注销成功」、online_check
实证 online:0）：

- 第一轮（10:38）暴露 **M2 通道登录从第一天起 100% 恒拒**的真 bug：`channelDeliver` 把
  第 4 参（门户 IP 1.1.1.2）误当「解析源」与通道源全等校验——真机上门户 IP 永远 ≠ 通道源，
  恒拒。单测用同值 127.0.0.1 掩盖了它（`TestChannelLoginRefusesMismatchedSource` 恰把 bug
  当特性锁）。**这也解释了 WiFi 掉线无人自愈的历史**：通道登录一直失败但无日志（日志
  同日才补）。修复：参数语义归位（portalIP），解析源一致性由 channelLogin 绑通道源解析
  结构性保证；真机形状测试（127.0.0.2 源/127.0.0.1 门户）锁住。
- 第二轮（10:46）修复版验收：**踢线 → 通道探测发现 unauth → 通道登录 16 秒闭环 →
  authed 恢复，主链路全程零中断**。M2-c 通过。

## 弹窗机制终局（踢线实时复现）

第二轮踢线后约 1 分钟内弹窗两次——因果链实时闭环：**任何「会话翻转」动作（踢线/
注销/守护重启期的状态翻转/切账号）→ WiFi 接口短暂门户态 → Windows 网络栈检测到
门户特征 → 自动拉起默认浏览器开门户页 1-2 次**。用户观察「基本都在项目开工期间弹」
的谜底：开工=守护频繁重启/踢线/切账号（网络状态反复翻转），稳态运行时不翻转就不弹。
monitoring/第三方程序嫌疑就此排除（flip-your-desk 的 fyd 测试浏览器为并行会话产物，
独立 profile 不写 Default 历史，与弹窗无关）。

治理分三层：
1. **稳态层**（已解决）：双通道守护维持会话 → 无翻转 → 不弹。
2. **翻转窗口层**（代价可接受）：踢线后 ~60-90 秒自愈窗口内的 1-2 次弹属恢复链路正常代价。
3. **感知层**（用户自决，一步到位）：Win11 设置 > 网络和 Internet > WLAN > STU 属性 >
   关闭「检测到需要登录时自动打开登录页」——Windows 不再自动弹，改为手动。
