## 8. 源失效自愈真机验证（2026-11-24 晚，v2.4.1 P0 改动）

> 验证 commit `8b2fb5c`（源失效自愈：注入 v4 重绑 + SourceStale 自愈缝）。
> 环境：小米 2211133C（MIUI），校园 WiFi STU，手机 IP 172.29.153.170，
> debug 签名版（同签名覆盖安装，Keystore 凭据保留）。无线调试端口当天多次变更，
> 换网前 41673、换网后 39365。

**操作与观测**：
1. 安装新 APK（lastUpdateTime 11-24 19:41）→ 点「启动 M1 守护」→ pid 31553，
   `19:43:19 拍: 在线`。
2. 触发换网：手机端延迟脚本 `svc wifi disable` → 6s → `svc wifi enable`（同 IP）。
3. 换网瞬间 `19:44:21 状态/拍: 离线｜... bind: cannot assign requested address`，
   **`19:44:30 状态: 在线`** —— **9 秒回在线**（对照 §7 簇1 40 分钟、簇2 4 小时）。
4. 换网后 pid 仍 **31553**（未重启守护）；`/state` = online、v4_src=172.29.153.170。

**判据结论（诚实）**：
- **换网后 1 拍内回在线 ✓**（9 秒，含一次 Doze/系统节流的拍间隔）；
- **无需重启守护 ✓**（pid 未变）；
- **机制归因存疑**：这次是「主动断 WiFi + 同 IP 恢复」，恢复事件同时触发
  NetworkCallback 与新增的 SourceStale 自愈缝，而 sourceLog（`物理源重新注入:`
  打印）只在 `Mobile.logsJSON()` 里、无 adb 导出入口，**无法单凭 cnalw.log
  区分是哪条路径生效**。代码证据（6 个单测覆盖 SourceStale 触发/同 IP 复位/
  并发防抖/端到端接线）+ trouble-maker 审查（2 阻断项已修）已闭合，但真机层
  不宣称「已证明走新缝」，只宣称「换网自愈行为成立」。

**没验证到的**：① 自然 Doze 深睡（非主动断网）下的自愈——需下一个过夜轮；
② extra v6 轮换后的重绑收敛（A5）；③ 不同 IP 的换网（DHCP 换了地址）。
