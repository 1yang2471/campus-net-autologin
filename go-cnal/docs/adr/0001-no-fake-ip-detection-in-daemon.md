# 不在守护侧实现「系统 DNS fake-ip 残留」自动检测

2026-11-23 排查「开关 TUN 后少数网站能开、多数打不开、过段时间自愈」时，
曾尝试在守护侧新增「系统 DNS 假 IP 残留导致网页打不开」的自动检测与告警。
**最终决定不实现**，只保留一键诊断脚本 `scripts/diag-dns-hijack.ps1`。

原因（两轮 ocr 机器审查钉死，代码层面无法绕过）：

1. TUN 代理（Clash/Mihomo 全系）**正常开着**时，系统 DNS 本就把域名解析到
   fake-ip 段（28./198.18.）——这是设计使然。单看「DNS 返回假 IP」会造成
   开着代理就常驻误报，并抢占 health.go 的 Reason 掩盖真实问题。
2. 「TUN 切换瞬间映射表丢失、缓存残留假 IP」与「TUN 正常工作返回假 IP」在
   DNS 应答层面**完全相同**，无法区分。
3. 曾试图用「用户路径判红」作第二佐证信号，但用户路径探针（`probeAnchor`）
   是 IP 直连（拨 `ProbeIPs` 如 223.5.5.5），**不做 DNS 解析**——DNS 层故障
   永远不会让它变红，佐证信号不成立，告警永远不会触发。

结论：守护侧的观测缝没有能可靠区分该故障的信号，硬做只会误报或永不触发。
诊断交给用户侧脚本：读系统 DNS **缓存快照**（TUN 切换前的残留）+ 新查询对比，
输出证据与「疑似」结论，由用户结合体感判断；修复走 `Clear-DnsClientCache`。

代价：出问题需手动跑一次脚本，而非面板自动提示。好处：零误报、零误导，
不往守护状态机里塞一个无法成立的观测量。
