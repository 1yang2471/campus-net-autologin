## 三、被否证的假设（防止下次会话重新怀疑）

1. **FlClash TUN 退出不清场** —— 否证（E6）：路由/DNS/代理均无残留。
2. **以太网静态公网 DNS 死路** —— 否证（E7）：NameServer 注册表为空，DHCP 纯动态；`Get-DnsClientServerAddress` 在断链适配器上显示的是租约残留缓存，不参与解析（本会话第一版判断即此误判，ipconfig /all 拉回）。
3. **锚点 404 = 校园劫持** —— 否证（E5）：锚点服务对 `Host: IP` 请求本就回 404，判定须走守护变体序（无 Host → 带 Host）。
4. **绑源 DNS 超时贴边（3s）** —— 否证：同参数实测 <10ms。
5. **「插线自愈」的单变量归因** —— 诚实存疑：插线（11:32）与风控窗 4.5h+16min 两个变量混杂，无法区分「链路 reset 触发 AC 重新放行」vs「风控窗自然到期」。下次复现时以「插线后 ≤3 分钟恢复」为观察判据继续采样。

## 四、三个内因（实测钉死，修复靶心）

### 内因 1：L2 观察被污染解析蒙蔽

L2 探测的解析缝用 campus_dns（10.129.17.10）解析大众站 → 钉假 IP → TLS 必死 →
「出口受限持续较久」4.5h 假警报（真 baidu 双协议 200）。今早存在两种死法被同一
读数混为一谈：

- **真·AC 拉黑**（06:31-11:32）：锚点死+用户路径死+会话绿，登录无效
- **假·DNS 污染**（11:33 后）：校园 DNS 返回假 IP，真网络通

### 内因 2：假在线组合文案误导

「在线」打头 + 用户体感没网。三读数组合（会话绿+锚点红+用户路径红 ≥10min）是
「AC 假在线」的精确度量，但状态词仍是「在线」、文案只说「勿反复重登」不说该做什么。

### 内因 3：rd 触发面窄

rd（源重发现）只在 OnPortalDown 触发；「绑源解析失败转系统栈」不触发重选，插线
恢复后 PortalAlive=true 也不触发。11:32 插线 → 11:42:20 route 恢复之间 10 分钟粘滞
（pt 缓存与 rd 触发面的复合；恢复瞬间的确切触发机制未定位——修复时先写测试钉行为）。

## 五、修复方案（下次开工，按优先级）

1. **L2 抗污染（双解析对照）**：L2 探测双路解析（campus_dns vs 系统栈）各测 TLS。
   两路分叉（campus 死、系统活）→ 改报「校园 DNS 解析异常（解析结果异常）」，
   与「出口受限」区分。判据：假警报形态（DNS 分叉）下文案不再说「TLS 被重置」。
2. **假在线文案升级**：会话绿+锚点红+用户路径红 ≥10min → 主状态词「会话在线｜
   出口被控」+ 指引（「重连救不了；等待恢复或换网络；可查梯子残留」）。
3. **rd 触发面拓宽**：chooseRoute 转系统栈时同步触发 rd 重选（5s 下限沿用）；
   插线恢复后绑源解析成功回 bound 的路径补测试钉行为。
4. **托盘菜单状态行瘦身**（用户 2026-11-22 点名）：`cmd/cnalw/statusline.go:8`
   把 Detail 全量拼进菜单行（如「出口受限持续较久（大众站 TLS 被重置≥10 分钟；
   认证正常；会话由 online_check 独立核实，勿反复重登）」几十字），撑开托盘
   菜单宽度。修法：菜单行只留主状态词 + 第一段短细节（括号补充说明不进
   菜单行），完整文案留给 tooltip 与面板——遵守「单源渲染」家规，截断规则
   放一处（statusline 或 Snapshot 短形态字段，开工时二选一定稿）。

修复走实现 agent → trouble-maker → tester 流水线；装机验证时用 E1-E8 同款实测
脚本核读数。**M2-c 同款注意**：实验不拿用户的网做破坏性动作。

## 六、用户侧建议（守护管不到的层）

- 11-21 与 11-22 两次事故共性 = **整夜挂机**。AC 拉黑窗诱因大概率是夜间代理流量
  特征（23:36 FlClash 启动后 L2 异常开始零星出现）。睡前关梯子是最直接的用户侧
  根治——守护不对抗校园风控（四层闸机 L2 不干预是设计边界）。
- 复发时快速自检口诀（从本次实测提炼）：**会话绿+锚点红+用户路径红 = 校园侧问题，
  重连无用，等待或换网络**——勿反复手动登录/注销（门户受理但 AC 不放行，白费）。
