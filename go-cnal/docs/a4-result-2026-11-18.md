> 场景：小旋风极速版（com.xxfapp.clients.apex）VPN 服务运行中，tun0 全接管
> （0.0.0.0/0 + ::/0，bypassable=false，Uids 覆盖全部 app）。核对工具：开发者页
> 「A4 出口核对」（A4Egress 两路：Kotlin 明文 HTTP / Go native 绑源，判定只看 Go 路）。
> 判据：testplan §4——门户侧看到的出口 IP = 校园网 Wi-Fi 地址。

## 一句话结论

**A4 按原判据不过**（VPN 下 Go 路出口核对失败）。A/B 对照钉死因果：
Go native socket 无 VpnService.protect 保护，被 per-uid 策略路由整体抓进 tun0
（gomobile 无法向 Kotlin 传递 socket fd 以调用 protect——官方只承诺 Java 层
socket 受 bindProcessToNetwork 影响，android-plan §4.2 预言的风险被真机证实）。
testplan §7 矩阵的降级路径「停止自动登录」有自动化产品解（见下），等拍板。

## 产品解候选（等拍板，~1h 工程量）

**推荐：VPN 检测自动暂停**——Kotlin 侧已有 NetworkCallback 唤醒通道，检测到
TRANSPORT_VPN 网络激活时热关 auto_reconnect（走既有 /config POST），发通知
「梯子已开，守护暂停自动登录」；VPN 消失自动恢复。理由：
- 防真实风险：VPN 下守护探测全失败会误判掉线 → 自动登录反复撞校园冻结线
- 不需要 protect（gomobile fd 传递不可行，已由本轮实测排除）
- 完全落在 testplan §7「A4 不过 → 停止自动登录」降级路径内

备选：用户约定手动关自动重连（零代码，靠自觉）；分应用代理白名单（依赖用户
配置，不算产品解）。
