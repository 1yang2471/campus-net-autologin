# 多网卡未认证与 Windows 联网指示（2026-11-19）

## 现场（全实测）

2026-11-19 上午，用户感知「校园网突然用不了」。分层排查结论：

| 层 | 实测 | 结论 |
|---|---|---|
| Clash 残留 | `FlClashHelperService` 在跑、7890 无监听、注册表残留 `ProxyServer=127.0.0.1:7890`（ProxyEnable=0） | 应用走死代理会全灭，直连没事——**“用不了”的第一元凶** |
| WiFi（172.29.153.x） | 锚点 204、NCSI 200、443 200 | 已认证、出口正常 |
| 以太网（10.141.53.x） | 锚点 204（白名单）、NCSI 探测 302 被劫持到门户、443 全部 refused | **已连接但未认证**（VLAN 白名单态） |
| Windows 联网指示 | 双网卡并存时取最差结果 → 「无 Internet」黄叹号 | 用户看到的是以太网未认证，不是 WiFi 断网 |
| DHCP | 租约一度 1 小时、一天多次换 IP（10:22/10:38/10:39/10:49 物理源切换） | 学校侧行为；后自行恢复为 8 天租约 |
| NCSI 注册表 | `EnableActiveProbing=0`（11-11 本项目排查「浏览器反复弹门户页」时手工关的，备份在 `%LOCALAPPDATA%\campus-net-autologin\ncsi-backup.txt`） | 当天已恢复为 1：未认证时自动弹门户页是正确引导 |
| IPv6 | 仅链路本地地址；DNS 返回 AAAA | 双栈应用先试 v6 再回落，表现为慢几秒 |

## 决策

1. **NCSI 注册表不产品化自动开关**：`HKLM` 写入需要管理员（实测普通权限 Access denied），
   自动化会弹 UAC、睡眠唤醒后状态不可控。改为把事实显示在面板：
   「其他网卡：10.141.53.34（已连接未认证；Windows 可能误报无 Internet）」。
2. **旁路网卡只观察、不登录**：登录出口仍只有当前绑定源一条（多凭据出口会放大
   门户反暴力冻结风险）。观察周期 60s、零凭据（一次绑源 DNS + 一次不跟随跳转的
   HTTP），结果进 `/state` 的 `unauth_sources`。
3. **兼容报告模板**新增 DHCP 租约时长、双网卡联网指示、代理残留三项观测，
   异校部署时可快速区分「学校侧网关行为」与「本机环境」。
