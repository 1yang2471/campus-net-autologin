### 关键判据冲突（第 4 问的实质）

- A1 要求「踢线后 ≤5s 恢复」；心跳 30s 时平均 15s、最坏 30s 才发现掉线 —— **数学上不成立**。
- A3 要求「≤3%/h」；3s 心跳稳态 ≈1,446 次网络操作/h，过夜粗算 6.07%/h（受插电/整机口径污染，只算红旗）。
- 两者同时成立的正解 = **事件驱动掉线发现**（系统网络回调即时唤醒）+ **低频兜底**（门户静默踢线 Wi-Fi 不断，回调不响），而非在「3s 还是 30s」里二选一。
- 诚实边界：事件驱动也**不能保证 ≤5s 对门户静默踢线**；若 A1 严格值仍不过，按测试计划 §1 的降级条款如实降级，不硬堆技巧。

## 2. 全清单（每项：判据 / 现状 / 阻塞物 / 需要谁提供什么）

### A1 息屏存活（30 分钟）
- 判据（2026-11-13 弱形态拍板后）：**进程/服务存活 + 亮屏后 1 拍内恢复**；恢复判据 = 踢线后按发现路径计（事件 ≤5s / 静默踢线 ≤5min 兜底）。
- 现状：**观测部分已过**（凌晨轮实证：进程存活 9h+、深 Doze 冻结 4h28min、07:01:27 亮屏即拍恢复，见 `docs/a1-result-2026-11-13.md`）；**恢复判据待踢线轮**。
- 阻塞物：~~心跳日志台架~~（已落地）；踢线轮待用户今天安排。
- 需要：注销手机会话制造踢线（**用户批准**，断网约 1 分钟，请记踢线时刻时：分：秒）。

### A2 夜间 Doze × OEM 阉割（8 小时）
- 判据：`BOOT_COMPLETED` 送达、服务未被杀、**每次被踢都恢复**、核对**门户侧**登录/会话日志（不信自家日志）。
- 现状：仅 MIUI 一台 9.5h 事后复原，且非连续监控；无 BOOT_COMPLETED 验证。
- 阻塞物：**EMUI 第二台机器**（计划原文要求 MIUI、EMUI 各一台）；门户侧会话日志导出权限。
- 需要：**用户提供 EMUI 设备**；或明确书面降级为「仅 MIUI 已验」。**→ 2026-11-12 用户拍板：书面降级为「仅 MIUI 已验」，不另行采购 EMUI 设备；A2 结论不得表述为全过。**

### A3 省电 × Wi-Fi 空闲超时（8 小时）
- 判据：`8h 不掉`；`心跳功耗 ≤3%/h`；`dumpsys batterystats` 前后 + 起止电量 + app 归因；若必须更短心跳才不掉，测出心跳下限。
- 现状：**无一次有效 A3**。过夜粗算 6.07%/h 但混杂 09:46 已插电、整机口径、adb 掉线、3s 心跳、白名单，只是风险信号。
- 阻塞物：无 batterystats/归因/基线；被测对象节拍与计划不符；唤醒锁 `acquire()` **无超时**，屏灭 + 登录被拒可无限期持锁。
- 需要：事件驱动 + 唤醒锁超时（工程）→ 再跑 8h 连续采集（**用户**：拔电、熄屏、别用手机）。

### A4 绑网正确性（最高风险项）
- 判据：FlClash/TUN 同时在跑时 `bindProcessToNetwork(Wi-Fi)` 下**出口正确率 100%**，切 Wi-Fi/蜂窝/VPN 各 3 次。
- 现状：A4 单点 `egressCheck` 真机验过 Go native socket 绑源；**未做 VPN/TUN 共存与 9 次切换**。
- 阻塞物：需要 VPN/TUN 环境与多网络切换操作（**用户**：装/开 FlClash、配合切网）。

### A5 手机 v6 现实
- 判据：校园 SSID 下存在可绑定 GUA；轮换后重绑 ≤3 次收敛。
- 现状：~~当前真机 `/state` 报 `v6_state=no_address`、`v6_src=（无）`~~ **2026-11-12 反转**：`ip -6 addr` 与 `dumpsys connectivity` 实测校园 SSID（STU）下发 **2 个 GUA**（`2001:250:3003:` CERNET 前缀，稳定+临时各一）——环境判据满足，原 `no_address` 是**应用缺陷**：`NetBinder.addrOf(lp,6)` 取第一个 v6 拿到 `fe80::` 链路本地（wlan0 地址序 [fe80, v4, GUA稳定, GUA临时]），`PhysicalSource.v6` 正确拒链路本地 → 注入空 v6。修复：`Bound` 携带全 v6 列表 + `CnalKernel.pickV6Source` 从列表挑 GUA（JVM 红灯测试用真机地址序列守）。装机复核：`v6_state=online`、`v6_src=2001:250:…:4112`、detail「IPv6 在线」。
- 阻塞物：~~校园 SSID 是否下发全局 GUA~~（已实测存在，缺陷已修复）；剩余判据=「轮换后重绑 ≤3 次收敛」待真机轮次。
- 需要：**用户**在校园 Wi-Fi 下确认 `ip -6 addr`；若无 GUA，按计划 §5 的降级条款「安卓砍掉 v6 卖点，只留 v4」如实落地，不宣称 A5 过。

### 性能与占用回归
- 判据：可复现的体积/内存/网络/电耗基线 + 回归闸。
- 现状：`Benchmark`=0、`pprof`=0、`-race` 跑不了（CGO 不可用）、无 CI；面板打开 WS 359.7MB（闲置 13.7×，来自未入库的一次性脚本）；`config.ini` 每次保存整文件重写；`cnalw.log`/`probe.log` 无 rotate；`sourceLog` 有 200 行上限但那是内存缓冲。
- 需要：benchmark/回归脚本（工程）+ 可复现测量台架（**用户**提供连续空闲机器时间）。

## 3. 工程队列（单方可做，按依赖排序）

1. **观测台架**：M1 每拍心跳日志（时间戳/状态/是否跳过）+ rotate（大小或行数上限），与状态迁移/事件同文件；补 `dumpsys batterystats` 采集脚本。（2026-11-12 代码核查：安卓 tickLoop 已每拍调 `Logger.Observe`，`Observe` 内部去重导致迁移才落行——挂接点现成，只差心跳行写入与 rotate。）
2. **事件驱动**：AAR 加 `Wake(reason)`；Kotlin `ConnectivityManager.NetworkCallback`（onLost/onCapabilitiesChanged/onLinkPropertiesChanged）→ 唤醒 Go 做完整 Tick；Go tick 改「回调唤醒 + 5min 兜底」；免认证窗口判定保持不变（2026-11-12 核查：全库无「免流时段降频」实现，免流窗口只改 Tick 判定分支、节拍从不变——原文「保留免流时段降频」无对应物，按现实措辞）。
3. **唤醒锁**：`acquire(timeout)` 上限 + 释放 watchdog，消除「屏灭 + 被拒无限期持锁」。
4. **README 通用性硬边界**（不扩范围）。
5. **性能回归**：最小 benchmark + 体积/请求数基线脚本，进 `go test` 门。**→ 2026-11-12 落地**：`dialect.Parse`/`InterpretHandshake`/`ParseOnlineCheck`/`Form.Fields` 四组基准（`-benchmem`）+ `TestParseAllocBudget` 分配闸（基线 12 allocs/op，预算 16，普通 `go test` 自动跑）；`scripts/bench-baseline.sh` 采集基线与三 exe 体积，首份基线 `docs/bench-baseline-2026-11-12.txt`（Parse 527.6ns/552B/12allocs）。pprof/-race 因 CGO 不可用维持不可用，不硬凑。

## 4. 依赖与诚实规则

- 工程 1–3 完成前，A1/A3 的严格判据**不具备测量条件**，不得宣称通过。
- A2 的 EMUI、A5 的 GUA 属**设备/环境阻塞**：要么用户提供，要么按测试计划 §2/§5 的降级条款书面降级；**不得用 MIUI 单台结果冒充 A2**、**不得在无 GUA 时宣称 A5 过**。
- 每次真机轮次启动前必须现场复查电源状态（第 4 轮作废教训）；无线 adb 过夜不可靠，A 系列连续轮次改 USB adb（若用 `dumpsys battery unplug`，结论须披露台架手段）。
- 全绿才收 = 上表每项都有判据原文 + 原始证据文件 + 阻塞物已消失；缺任一项，报告里写「未验证」而不是「通过」。
