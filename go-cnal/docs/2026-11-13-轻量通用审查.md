# 轻量/通用审查（2026-11-13）

> 起因：风控可见化上线后，按用户要求对全项目机制做一遍「是否满足最初需求」的审查。
> 最初需求：**轻量、通用**。判据从第一性原理重述如下，量化以今晚实测为准。

## 判据（第一性原理重述）

- **轻量** = 守护对机器不可感知：资源占用可忽略、探测预算不挤占校园侧容忍度、
  磁盘有界、依赖面小。反述：一个需要用户惦记的守护就是失败的守护。
- **通用** = 边界内的场景覆盖，不是跨校协议通用。README 边界（2026-11-12 拍板）：
  ac_portal 族、参考校已验证、**异校不立项**——「异校可配」是设计目标不是已验证事实。
  通用性真正的判据：**同一份内核不改动地跑在三种壳**（托盘 cnalw / 无头 cnald /
  安卓 AAR），通用性住在组合根，不在内核。

## 轻量：实测

| 项 | 实测（2026-11-13 晚） | 评价 |
|---|---|---|
| 体积 | 三 exe 7.0 / 7.8 / 8.6 MB（`-s -w` 剥符号），zip 9.9 MB | 硬盘可忽略 |
| 内存 | cnalw 工作集 25.3 MB（PID 14260） | 常驻可忽略 |
| CPU | 启动 ~4 分钟累计 0.1s | ≈0 |
| 探测预算 | interval=3：L1 1200/h + L2 60/h + v6 60/h + 会话 60/h + 流量 6/h ≈ **1386 次/h ≈ 0.4 req/s** | 噪音级；登录类另有 30s 闸 + 3 拍去抖 + 8 次/h 上限 |
| 日志 | 3s/拍 ≈ 68B → ~1.9 MB/天，10+10MB 封顶（安卓 5+5） | 磁盘有界 |
| 依赖 | 直接依赖仅 systray(+webview2)、x/sys；x/mobile 仅构建期工具链 | 供应链面小 |
| 代码量 | Go 源码 9145 行 + 测试 10246 行；Kotlin 1894 行 | 单人可维护 |
| 安卓 | AAR 5.9 MB；debug APK 36 MB（未剥符号，非发布形态） | 可接受 |

**探测预算的真实红线是登录，不是探测**：校园侧实测冻结线 12 次登录/h（E14），
守护上限 8 次/h + 30s 最小间隔 + 3 拍去抖；2026-11-13 登录风暴（每小时 8+ 次
主动撞线）已堵。探测本身（0.4 req/s）对门户是噪音级。

## 轻量：今晚暴露的两个非资源性问题

1. **旧进程 21:20:10 停搏事件**：心跳 3s 节拍干净地停在 21:20:10，无迁移行、
   无错误行；事件日志无崩溃（WER 里只有 cs2.exe 的内存泄漏报告）、无睡眠事件。
   **非崩溃、非休眠，最可能是人为退出**（用户在场，22:40 在跑 cs2）。两个推论：
   - **校园会话的持久性 > 守护的必要性**：守护缺席 2 小时网络一直可用——守护的
     价值不在「维持在线」（会话自己就能活），而在「被踢后 30s 内复活」。这直接影响
     产品定位：守护挂掉≠断网，用户痛点只在踢线窗口。
   - **停搏无自我暴露**：托盘图标消失是唯一即时信号，但没人盯托盘；心跳断档只有
     事后翻日志才发现。建议（未实施）：启动时检查上次心跳时刻，gap 超阈值写一行
     「上次心跳停于 X（间隔 Y）」——20 分钟量级，把停搏从「翻日志才知道」变成「启动即告」。
2. **interval=1 是脚枪**（2026-登录风暴的根因之一）：下限钳制 ≥3s 或保存时警告，
   仍未做（30 分钟量级）。

## 缺口与建议（不实施，等拍板）

1. **AAR 重编装机**（最高优先）：PC 侧今天的四修（去抖/登录尝试日志/tz/停搏…）
   都不在手机上的旧 AAR 里——手机跑的还是旧引擎。随下次 A1 轮次一起装机验证。
2. interval 下限钳制（脚枪，30 分钟）。
3. 心跳停搏自我暴露（20 分钟）。
4. l2Host 升配置项（可选，收益低）。
5. A3 电耗轮、A4+A5 轮次照旧排队（采集脚本已备）。
