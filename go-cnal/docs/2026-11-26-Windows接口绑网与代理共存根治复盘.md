# Windows 接口级绑网与代理共存根治复盘（2026-11-26）

## 1. 触发与现场

用户连续遇到“开加速器后整机断网一段时间，随后自行恢复”。11-26 的日志显示：

| 时间 | 事实 |
|---|---|
| 12:38:44 | 守护最后一次正常心跳 |
| 12:38:46 | FlClash 写入运行数据 |
| 12:38:47 | 物理锚点异常，门户会话仍在线 |
| 12:38:51 | 开始报出口受限 |
| 12:48—13:07 | 用户拔插网线、切换 WiFi 尝试恢复，网络状态被进一步混杂 |
| 13:23:27 | 恢复在线 |

初始故障早于拔线，且门户会话始终正常；因此不是认证态丢失，反复注销重登没有依据。日志与 11-21/22 的 AC 假在线长窗同型，但本次还暴露了一个本地代码缺口：Windows 物理栈只绑了源 IP，没有绑接口索引。

## 2. 已确认的代码根因

原实现：

- TCP 使用 `net.Dialer.LocalAddr`。
- DNS UDP 另建一个只绑 `LocalAddr` 的 Dialer。
- 门户 TLS 探测直接创建只绑源的 Dialer。
- `Bindable` 只调用 `net.ListenUDP` 绑源。

这些动作都不能阻止路由型 TUN 接管 socket。`auto` 模式还允许绑源失败后转系统栈，因此即使增加接口绑定，也不能单独保证凭据绝不进代理路径。

## 3. 修复内容

### 3.1 接口级绑定

- Windows 在 socket connect/bind 前设置 `IP_UNICAST_IF` / `IPV6_UNICAST_IF`。
- IPv4 接口索引按网络字节序写入，IPv6 使用主机字节序。
- 源 IP 每次重新解析到唯一、up、索引非 0 的本机接口；同 IP 多接口时 fail-closed。
- 不缓存接口索引，适配同 IP 重连和网卡重建；门户 DNS 缓存按源 IP 分键，一次操作使用源与 pin 的不可变快照。
- `campus_dns` 留空时从物理接口读取同族 DNS，取不到则严格模式明确失败。
- HTTP、DNS、门户 TLS、Bindable、IPv6 Peer、多通道登录共用同一绑定模式。
- 非 Windows 保持原 `LocalAddr` 行为，Android 共享包编译通过。

### 3.2 严格凭据路径

- 新增 `strict_interface_bind`，Windows 默认 `true`。
- 严格模式下 `auto` 遇到接口/绑源失败也 fail-closed，不转系统栈、不发凭据。
- 显式 `false` 才降级为仅绑源 IP；状态显示 `source_only` 与 `bind_degraded`。
- `net_mode=system` 仍是显式专家覆盖，不伪装成物理栈。

### 3.3 Clash/Mihomo 联动

- 新增仅本机回环 HTTP 的 `clash_api_url` / `clash_api_secret`。
- 登录、补绑、通道登录被门户接受后调用 `POST /cache/fakeip/flush`。
- 2 秒超时，禁用代理环境变量；拒绝子路径与重定向；失败只告警，不改变认证结果。
- flush 异步执行并合并 pending 请求；非法配置只告警并禁用联动，不阻断认证启动。
- 不调用 `/connections`，不记录 secret。

### 3.4 可观测性

- `/state` 新增 `bind_mode`、`bind_interface`、`bind_index`、`bind_degraded`、`bind_error`。
- 门户路径文本与 `cnal status` 显示接口绑定或降级。
- 兼容性报告模板要求提交代理模式和绑定诊断。

## 5. Windows 真机 TUN A/B（15:26—15:28）

| 场景 | 系统事实 | 守护事实 |
|---|---|---|
| FlClash 未运行 | 仅物理 WLAN，系统代理关 | `bind_mode=interface`，`WLAN 2(#9)`，在线 |
| FlClash 核心启动、系统代理开 | `ProxyEnable=1`，无 TUN 网卡 | 接口与健康状态不变 |
| FlClash TUN 开 | `Meta Tunnel` 网卡 up，默认路由指向 TUN | 仍 `WLAN 2(#9)`，在线，无绑定错误 |
| TUN 开时查看 FlClash 实时连接 | 列表未出现 `cnalw.exe` | 门户路径仍为接口绑定 |

这组实测证明：在路由型 TUN 开启且默认路由被接管时，守护仍绑定物理 WLAN，FlClash 连接列表没有接管 `cnalw.exe`。

## 6. 未覆盖与诚实边界

- WFP 按进程重定向的游戏加速器不等同于路由型 TUN，接口绑定不能保证绕过。
- 校园 AC/DPI 出口限制窗仍无法本地修复。
- 本次未做休眠/唤醒、拔插网线、DHCP 同 IP 重关联的真机矩阵；这些场景有单元回归，但没有新增真机数字。
- 未配置真实 FlClash external-controller，因此 Clash API 的真机 flush 未测；模块行为由本机 HTTP 替身覆盖。
- 本期不发布 Android，APK 保持 v2.4.1-go 资产不变。

## 7. 结论

本地可根治的部分已经落地：Windows 物理栈从“仅绑源 IP”升级为“源 IP + 接口索引”，严格模式阻止凭据回退系统栈，TUN 真机 A/B 通过。外部 WFP 重定向与校园策略仍属于产品边界，不能在发布说明中承诺“所有加速器永久免疫”。
