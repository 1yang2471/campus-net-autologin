# 设计与规格：双栈认证修复 + Go 跨端移植（go-cnal）

日期：2026-11-06 ｜ 状态：待用户复核 ｜ 相关产品：campus-net-autologin v1.0.10

## 0. 一句话

校园网门户的登录本来就是一条**双栈认证**协议（`ipv4or6` 字段），现版本从未发送它，
所以守护能把 v4 登回去、却永远登不回 v6——用户只能靠浏览器手动重登。本文同时给出
该缺陷的修复方案，以及承载它的跨端（Windows + Android）Go 实现的分阶段计划。

## 1. 本轮实测证据（全部 2026-11-06 于用户机器复现，汕大 a.stu.edu.cn，FlClash TUN 在跑）

| # | 证据 | 结论 |

| E1 | 门户前端 `/ac_portal/share/res/js/logic_new.js`：页面加载先向**对端栈**发 `POST opr=（双栈在线查询操作名）`（v4 页面问 `http://[1::2]`，v6 页面问 `http://1.1.1.2`），响应 `{success, ip, isOnline}` 存入 `g_ipv4or6`；`onPwdLogin` 经 `syncGetIpv4or6()` 把 `params.ipv4or6 = g_ipv4or6` 带进登录 POST；`onLogout` 同样携带。JS 注释原文 `//ipv4,ipv6一次认证` | 登录协议含双栈字段，浏览器一直在发 |

## 2. 目标与非目标

目标
- G1 让 v6 会话成为守护的一等状态：能观测（按平面、绑源）、能判定、能自愈。
- G2 一份协议实现同时服务 Windows 与 Android；两端功能项齐全（UI 外壳各一份，见 §4 决策 1）。
- G3 Windows 产物磁盘体积下降；**内存不承诺下降**（E15：Go+WebView2 在 Windows 上更费内存，
  故 Windows 保留 Tkinter 外壳）。
- G4 保留现有测试资产的保护力：把 E1-E9 的真实响应录成协议夹具，任何实现跑同一套契约。

非目标（明确不做，防膨胀）
- 不做 iOS；不做应用商店签名与上架；不做插件系统；不换配置格式；不做远程升级服务器；
  不绕过出口 DPI 管控（工具解决登录，不解决校方策略——沿用现版本边界）。

**被这批砍掉的**：自动补绑的 60s 状态机。理由是数据缺口，不是工作量——
**"v4 被踢时 v6 是否同掉"此前从未观测**。当晚已补测（`v6_kick_observer.py`，9 分钟 / 67 次采样，
只做无凭据握手不碰会话）：

```
采样 67 次；v4 离线 0；v6 同掉 0；v6 单独死 0；两平面不可观测 0
守护日志窗口内事件 1 条：20:35:52 INFO 自动重连成功
```

**这个 0 不能当证据**：守护典型恢复 ≤4 秒，我的采样节拍是 8 秒——v4 的离线瞬间**注定抓不到**，
所以"v6 单独死 0 次"很可能只是"没看见"。诚实结论：方向上支持"搭车 + 一键补绑够用"，
但不构成证明。立项判据改为长期零成本计数——守护在既有的重登日志行里顺手记一条对端握手态，
攒满一天再算 `v6 单独死` 次数：**>0 才立项自动补绑；=0 则 §5.2 矩阵第 2 行永久保持"仅手动"**。
计数逻辑属切片二，本批不做。

**体积瘦身推迟并改法**（#15）：`*.spec` 被 `.gitignore:15` 忽略且未被 track，
`build_exe.py:26-56` 每次重新生成——**写进 spec 的 excludes 在干净检出即蒸发**。
所以裁剪参数只能进 `build_command()`（`--exclude-module` + PIL 子模块），
且必须在干净检出重出包后实量 dist 才算数。它不疼、不紧急，且属于 M1 可能整体替换的部分。

**Go 移植（M1-M3）现在不写一行代码**：迁移的唯一理由是安卓，
而安卓的前提（A1-A5，见 §11）尚未在真机上立测。前提不过线，迁移的正当理由同时消失——
届时 Windows 侧继续留在 Python（外加 M0 的安全/体积修复），这比"为了换栈而换栈"诚实。
先做的语言无关投资：把 `tests_tdd.py:2987-3078` 的有状态 AC 模拟器 `_sim_ac_split`
升级成场景脚本（表驱动 stimulus→expected），它既保护 M0 热修，也是将来任何实现的第一份裁判。

## 4. 架构

```
go-cnal/
  internal/protocol/   ac_portal 族协议：指纹判族、表单、登录/注销、userflux、
                       新增 双栈在线查询 握手；响应词表可配置（沿用现 [response] 节）
  internal/netstack/   物理栈客户端：源地址绑定(v4/v6)、校园 DNS 解析、钉 IP、自签 TLS 可选、
                       头注入防线；平台差异集中于 build tag 下的两个文件
  internal/keeper/     状态机：L1/L2/L3 + 双栈会话矩阵、退避、熔断、免认证时段、节流
  internal/store/      config.ini 读写（沿用现格式与节名）；凭据：Windows Credential Manager
                       / Android Keystore，绝不写入 ini
```

关键决策
1. **协议实现只有一份，UI 有两份外壳——这是 E15 逼出来的取舍，不是设计偏好**：
   Windows 复用已验证、且常驻只有 17 MB 量级的 Tkinter 外壳；Android 用同一份 API 契约渲染
   web 面板（系统 WebView）。两份 UI 共吃的仍是 `internal/api` 同一契约，因此"全功能对齐"
   的判据是**契约字段与动作集合一致**，而不是像素一致。UI 层的实际新增只有一份（web 面板）。
2. **协议层零平台分支**：所有 OS 差异压进 `netstack` 与 `cmd`。这条是现版本最松的环节
   （`_raw_http` 里 `AF_INET` 写死 `keeper.py:246`，`validate_bind_ip` 直接把 IPv6 拒掉，
   DNS 只发 A 记录 `:386/:426`，v6 源发现完全缺失 `:646-686`）。
3. **契约层延续 `shell/kernel_api.py` 的既有接缝**（`STATE_LABELS`/`STATE_COLORS`/
   MockKernel），新增 `v4_session`、`v6_session`、`peer_addr`、`v6_source` 四个字段。
4. **Android 的网络选择归 Kotlin**：`bindProcessToNetwork` 是 Java framework API，Go 调不了；
   由 Kotlin 侧选出校园 `Network` 并绑定，把状态注入引擎，`netstack` 只负责绑源与钉 IP（§11）。

## 5. 双栈状态机（G1 的核心）

### 5.1 观测语义：三态改四态，"未知"不再当"不可达"报

真值来源：`POST 双栈在线查询` 到对端入口，**绑本端校园 v6 源、目标钉死 IP**，每 60s 一次，
与 L2/L3 同拍；**不绑源的结果一律丢弃**（E7：TUN 下不绑源选出的是隧道源，读数属于代理不属于校园）。

| 态 | 判据 | 面板/托盘文案 | 是否可据此行动 |
|---|---|---|---|
| S0 无 v6 | 本端选不出全局 v6 单播地址 | **完全静默**（多数校园终端本就无 v6，常驻负面文案制造"我坏了"的焦虑，违背不打扰原则）；仅在设置页与 compat 报告呈现 | 否 |
| S1 不可观测 | 有 v6 地址，但拿不到对端入口 / 绑源后握手无响应（含被 TUN 接管而不可观测） | "IPv6 不可观测（本门户无查询入口，或代理接管）" | 否——**现状把它报成 False + "双栈应用可能变慢"是误报**（#8） |
| S2a 在线 | 握手 `isOnline:true` | "IPv6 在线" | 否 |
| S2b 未在线 | 握手 `isOnline:false` | "IPv6 未在线（可补绑）" | **是**，见 5.2 |

另修一处读数陈旧：`_v6_state` 现在只在在线分支更新（`keeper.py:1294-1298`），
v4 掉线整段期间用户瞥见的是**掉线前的旧值**——v6 观察必须脱离在线分支门槛，与补绑探测同拍。

### 5.2 处置矩阵

| v4 | v6 | 动作 |
|---|---|---|
| 在线 | S2a 在线 | 无 |
| 在线 | S2b 未在线 | **第一批只给手动**：面板"一键双栈补绑"发一条带 `ipv4or6` 的登录；自动循环待 §3.1 观测闸门 |
| 在线 | S1 不可观测 | 无动作，文案见 5.1 |
| 在线 | S0 无 v6 | 无动作、无文案 |
| 未在线 | — | 现有重登路径**搭车**携带现场查到的 v6 地址 → 一次登录同时恢复双栈（E4 已证） |

### 5.3 预算、会话定义与多设备（第二轮审查 P1-7 补全）

- **会话的定义**（原文"单会话生命周期"歧义）：两次「v4 判死 → 成功重登」之间为一段会话。
  补绑预算按此计数，不按进程寿命、不按自然小时。
- 补绑与重登**共用同一个登录频率桶**，桶上限按 §3.1 第 1 项修正后的真实速率（≤8 次/3600s）。
- **补绑假阳性**：补绑后 60s 内复查 `isOnline` 不转真 → 计一次假阳性，复用现成
  `SESSION_FALSE` 自停机制（连续 3 次即停用补绑），不动 v4 判定。
- **免认证时段 / 冻结闸门 / DPI 窗口内一律不补绑**（沿用现版本压制逻辑）。
- **多设备未爆弹**：E12 已证 `userflux` 是账号级表、无栈维度，因此双守护**无法**区分
  "我绑的 v6"与"对方绑的 v6"。若 AC 的 v6 会话是按账号单槽（后绑覆盖前绑），两台设备
  会各自 60s 观察→各自补绑→ping-pong，合计登录频率把**两端一起**送进冻结。
  机制未知，不许猜：按 §11 V1/V3 实测后再定默认值；实测前手机侧补绑默认关。
- **同屏指令冲突**（P1-6，实用性要害）：DPI 窗口文案是"认证正常，勿重登"，而补绑恰是发一条登录，
  用户看到"勿重登"+日志"自动重连成功"会误判守护失职，可能去门户**手动注销**（那才真延长风控）。
  文案统一为："DPI 风控窗口：勿手动注销/重登；IPv6 自动补绑不属于手动重登，无需干预"，
  并加断言：裸串"勿重登"不得再出现在交付文案里。
- **托盘与面板必须同源**（P1-5）：现状面板吃 `state_detail`、托盘吃 `describe_state()`
  的平行硬编码字符串（`keeper.py:1237-1252` vs `:1307-1315`），双栈新状态托盘一个都看不见，
  熔断停时也只显示"离线"丢掉"可手动重连"指引。改法：`describe_state()` 单源渲染 `state+detail`，
  删平行分支；契约测试断言二者语义等价。

## 6. 通用性：对端入口不得写死学校

`[1::2]` / `1.1.1.2` 是汕大实测值。`keeper.py:61-63` 白纸黑字立着"各校差异一律走
config.ini / 面板，不再内置参考校地址"，`DEFAULTS`（`:64-91`）至今零校址——**这条家规
必须原样背诵进 Go 的 DEFAULTS，零校址**。

发现顺序（前一条命中即停，任一步失败即静默关闭功能）：
1. 配置项 `v6_peer` / `v4_peer`（默认空 = 双栈功能关闭；注意两端点 scheme 与端口不对称，
   v4 走 443、v6 走 80，所以是两个独立键，不是一个地址换端口）。
   配套 `[keeper] dual_stack = auto|on|off`（三态，`off` 即一键回退，升格为配置契约）。
   **`ipv4or6` 的值不进任何用户配置通道**——它必须每次现场查询（§5.3 末条：v6 临时地址轮换）。
   也不走 `[form]`：`[form]` 的契约是**静态字面字段**（README:189-190 自己写明），要表达
   "值需现场查询"就得引入 `${dyn:...}` 占位符 DSL，把配置文件升级成半门语言——梯子第 1/5 级
   都不允许，且目前只有这一个已知 provider。协议层用内部接口：`provider.fetch() -> 值|缺失|失败`，
   **缺失**则请求体不含该字段，**失败**不等于缺失（要可观测）。
2. 从门户登录页引用的 JS 中提取对端 URL 字面量。校验极严：只接受 **IP 字面量**
   （IPv6 必须中括号形式）、scheme 白名单、拒绝环回与链路本地、只接受默认端口——复用现版
   `parse_portal_location`（`keeper.py:440-477`）与 CRLF 头注入防线（`:240-243`）；
   抓回的 JS 是**外部不可信输入**，响应体必须设硬顶（现 8192B 读循环对 JS 文件不够）。
   提取到的对端**只允许承载无凭据握手**（§7 有字节级断言），凭据永远只发往用户确认过的 `server`。
3. 提取成功后做一次**无凭据自校验**：候选地址必须回 `{success:true, …, isOnline:bool}`
   形态才采纳。异校 JS 结构不同 → 提取失败 → 功能静默关闭，零误伤。
   **v6 源发现只能靠这个自校验**：`UDP connect 校园 DNS` 那套选路技巧在 v6 失效
   （`campus_dns` 是 v4，而对端字面量又被 metric 0 的 TUN 截胡，E7 实证），
   所以实现是"枚举物理适配器上的 AF_INET6 全局单播（排除 `fe80`/`fd`），逐个绑定试探，
   以握手有响应者为证"——歧义与失效在同一步里被消掉。
4. 向导里把提取结果显式展示给用户确认后才写盘，不静默改配置。

### 6.1 多候选歧义的选取规则（第二轮审查 P0-2：原文只定义了步骤顺序，没定义同一步内取哪个）

汕大登录页的 JS **同时**含 `[1::2]` 与 `1.1.1.2` 两个字面量（E1）。v4 登录链路要的是
**v6 对端**，取错即补绑必败、还白耗 §5.3 的预算。规则写死：

1. 从 JS 收集全部 URL 字面量，按字面量形态分类：带中括号的 IPv6 / 裸 IPv4。
2. 需要 v6 对端时**只接受带中括号的 IPv6 字面量**；需要 v4 对端时只接受裸 IPv4。
3. 同类候选 >1：取**首个全局单播**（排除 `fe80::/10`、`fd00::/8` ULA、`::1`）。
4. 仍歧义（多个 GUA 无法判定）→ 置为 S1 不可观测，**不猜**，一行日志说明候选集。
5. 混淆/字符串数组化/拼接形态：正则 0 命中 → S1 静默降级，不报错、不发包。
6. 对端为**域名形态**：直接拒绝（不发 AAAA，YAGNI），但**必须**落一行日志，
   并在 README「异校适配」写明这条已知限制——沉默降级会让用户把"不支持"当"坏了"，
   反复手动自救，反而触发重登。

判据表（这 7 步现在**全仓零实现、零测试**，`grep ipv4or6 *.py` 无一处；必须逐步先红后绿）：

| 步 | 输入形态 | 期望 |
|---|---|---|
| 1 | `v6_peer` 已配置 | 直接用，零探测请求 |
| 2 | JS 含 0 / 1 / N 个字面量 | N>1 按上面规则选；歧义 → S1 |
| 3 | 混淆、拼接 | 0 命中 → S1，不发包 |
| 4 | 域名 / 带端口 / 非 http(s) / 无括号 IPv6 | 逐一拒绝 |
| 5 | 握手响应四态（S0/S1/S2a/S2b） | 夹具 F1 + **请求体无凭据字节断言** |
| 6 | 补绑后 isOnline 不转真 | 2 次即本会话停用补绑，复用 SESSION_FALSE，绝不动 v4 判定 |
| 7 | 任一降级出口 | 断言"零 v6 请求发出" + 一行日志 + 文案为"不可观测"（不是"不可达"） |

**已删除的错误设计**：先前考虑"在本端 v6 /64 段内有限探测对端"——汕大对端是 `1::2`，
与用户前缀 `2001:250:3003:aa29::/64` 根本不同段，该法在参考校**必然一无所获**，还会向
陌生邻居发包（校园网里的攻击性行为，违背"不对抗、不碰系统设置"的产品姿态）。作废。

## 7. 回路 API 安全模型（Android 上 127.0.0.1 对同机所有 App 可达）

要害先说清：**token 失窃 ≈ 凭据失窃**，因为面板能改 `server`，而守护会把账号与密码原样
POST 到攻击者主机——现实现只在"解析得到 IP"处把关（`keeper.py:1030-1046`），不校验 host 指纹。

- 地址：只 bind `127.0.0.1`（字面量，不用 `localhost`，避免断网时解析歧义白屏）；端口随机。
- 认证：token 走 **`X-CNAL-Token` 请求头**，绝不放 URL（放 URL 会泄进 WebView 历史与日志抓取面）。
  SSE 带不了自定义头 → 用 `POST /stream/ticket` 换**一次性短时效 ticket**，用后即焚。
- 拒绝类：严格校验 `Host: 127.0.0.1:<port>`（防 DNS rebinding）；**完全不发 CORS 头**；
  所有状态变更一律 `POST` + `Content-Type: application/json`（废掉简单表单 CSRF）；
  无 token / 错 Host / 恶意 Origin 一律 401/403，并且这三种是**契约测试的负例**，不是口头承诺。
- 高危面单列：改 `server` 走独立端点，需面板二次确认 + 审计日志一行；`/settings` 快照
  **永不回显 password**（Python 侧已有"运行态/磁盘态占位分离"的纪律：`app_main.py:71`、
  `shell/credentials.py:14`，Go 里最容易在"整个 cfg 序列化"时破功）。
- **无凭据的字节级保证（E16，第二轮审查 P0-3）**：握手请求体只含操作名，实测无需任何凭据即可
  拿到 `{success, ip, isOnline}`；但这必须是**代码约束而不是观察结论**——对端请求构造函数
  一律拒绝携带 form 的任何键，契约测试里对端替身一旦收到含 `pwd=`/`userName=` 的请求即 FAIL
  并告警。理由：对端地址来自门户 JS 的字面量（外部可污染面），若握手按账号查询，
  提取链就变成账号枚举通道。
- 凭据来源：只从凭据管理器/Keystore（或环境变量）读；源码、示例、测试、夹具一律不含可用凭据。
- WebView：Android 用 `network_security_config` 只对 loopback 放开 cleartext，不开全局
  `usesCleartextTraffic`；Windows 走 WebView2，禁与外部域通信。
- 日志：写出前脱敏。现版 `_redact` 只打码 userName 不打码 pwd（`keeper.py:1437-1439`），移植时补齐。

## 8. 配置与凭据迁移

- `config.ini` 格式与节名不变（`[keeper]`/`[form]`/`[response]`/`[accounts]`），Go 直接读旧文件，
  用户升级零重配；新增键有默认值。编码沿用 utf-8-sig 兼容与值清洗规则。
- 密码从 Windows 凭据管理器按用户名读取（同名服务键），迁不动的场景保留"面板补密"路径。

## 9. 测试策略（对齐 tdd 技能：一次一个红灯→绿灯，纵向切片）

夹具（协议契约，Python 与 Go 两份实现跑同一套）

行为级用例（按优先级，每条先红后绿）
1. v4 在线 + v6 有地址未在线 → 恰好发一条带 `ipv4or6` 的登录，v6 转在线后不再发。
2. 被踢 → 重登请求体必须携带 `ipv4or6`（当且仅当现场查到了 v6 地址）。

5. v6 探测必须绑源：存在更低度量的 v6 默认路由（TUN）时，仍走校园源地址（E7 回归锁）。
6. 无 v6 地址的机器上，全套行为退回纯 v4，面板不出现 v6 文案，不发 v6 请求。
7. 异校降级：拿不到 `v6_peer`/`v4_peer`（或握手自校验不过）时不补绑、不报错、不写死汕大值。
8. 免认证窗口内不补绑、不判死。

必须保留为集成测试（夹具测不出来的时序类行为）
跨免认证窗口边界、**登录速率上限（E14 的滑窗断言）**、熔断停时与恢复、`userflux` 假阳性自停
（3 次→停 1 小时）、踢线风暴下的退避叠加、TUN 共存探测、config 迁移与多账号切换、面板即时生效。

## 11. Android 形态（G2；按审查 P0-6 重写）

**先讲运行形态的硬约束（原方案在这三处是空洞）**
1. Android 10+ 禁止执行 app 私有目录里的可执行文件 → "带个 Go 二进制跑" **不成立**。
   引擎必须经 `gomobile bind` 编成 `.aar`（内含 `.so`）由 Kotlin 进程内调用。
2. `bindProcessToNetwork()` 是 **Java framework API，Go 调不了**。原方案把它放在
   `internal/netstack` 是层级错误。正确分层：**Kotlin 侧做网络选择器**——
   枚举 `Network`，挑 `TRANSPORT_WIFI` 且不含 `NET_CAPABLE_VPN` 的那个，
   `bindProcessToNetwork()` 绑定后，把"当前是否处于校园网络"作为**回调/状态注入**给 Go；
   Go 只管绑源地址与钉 IP，不试图决定走哪个 Network。
3. 后台存活不是"150 行 Kotlin"：前台服务类型（Android 14 必须声明，走 `specialUse`）、
   API 33 通知运行时权限、`ACTION_IGNORE_BATTERY_OPTIMIZATIONS`、国行 OEM 自启白名单引导 UI、
   `BOOT_COMPLETED` 在多家 ROM 被阉割——按 **400-600 行**预算。

**产品前提必须先立测**（**M3 手机侧**的准入闸门；2026-11-06 晚用户拍板 Go 引擎先动，
所以这组测量的位置从"迁移前置"改成"手机切片前置"——风险随之转移到 M3，
缓解是切片一/二的 Windows 引擎本身可独立交付，安卓失败不带走全部投资。方法写死，不靠自家日志自证）：

| # | 判据 | 方法 | 通过线 |
|---|---|---|---|
| A1 | 息屏存活 | 前台服务 + 电池优化白名单，息屏 30min；`adb shell dumpsys deviceidle` 对照时间戳 | 漏拍 0；模拟踢线后 ≤5s 恢复 |
| A2 | 夜间 Doze × OEM 阉割 | MIUI 与 EMUI 各一台过夜 8h；`BOOT_COMPLETED` 送达、服务未被杀 | **以门户侧登录日志计数**（不信自家日志）：每次被踢都恢复 |
| A3 | 省电 × 空闲超时 | 息屏过夜，观察 Wi-Fi 空闲超时是否踢会话；60s 心跳本身即流量 | 8h 不掉；若必须靠心跳才不掉，测出心跳下限并折算电耗——**>3%/h 则产品形态降级** |
| A4 | 绑网正确性 | `bindProcessToNetwork(Wi-Fi)` 且 FlClash 同时在跑，核对门户/握手侧看到的出口 | 平面正确率 100%，否则安卓探测整体不可信 |

任一条不过，手机侧形态**降级重议**而不是硬堆后台技巧，候选形态按代价排序：
(a) 仅解锁/前台时可交互守护 + 通知栏一键重连；(b) Wi-Fi 连接广播触发的一次性登录
（等价于 README 原先建议的 MacroDroid 形态，成本最低）；(c) 路由器侧（OpenWrt 插件）替全宿舍兜底。

### 11.6 已量到可用结构信号（取代 §11.5 的冻结状态，v3）

E25 实测：`Get-NetAdapter` 给出 `ifIndex 10 WLAN 2 = Realtek 8852BE Wireless LAN WiFi 6 PCI-E NIC`、
`ifIndex 36 FlClash = **Meta Tunnel**`；而 `Win32_NetworkAdapter` 的 `InterfaceType` **返回空**、
`PhysicalAdapter` 对 Meta Tunnel **报 True**。两个"看起来最正规"的判据当场是假的：

- ❌ 用 `PhysicalAdapter`/`InterfaceType` 区分物理与隧道——TUN 自称物理设备；
- ❌ 按适配器**名字**过滤（现有 `VIRTUAL_NIC` 的做法）——名字是用户起的（`FlClash`），
  里面没有任何关键词，所以这条防线一直在漏，才让 `"28."` 前缀成了唯一挡箭牌。

✅ 可用信号是**驱动声明的适配器描述**：`Meta Tunnel` 含 `tunnel`，而真实无线网卡描述含
`Wireless LAN`/`GbE Family Controller`。它由驱动作者写死、不由用户配置，因此既不绑学校
也不绑具体代理软件名，同时解决 E21（本机 TUN 用 28. 必须排除）与 E22（他校内网用 28./8
不得被误排除）两个相反方向。

落地要点（下一步实现时照此，别再猜）：

1. 数据源用 `GetAdaptersAddresses`（ctypes，`AdapterDescription` 字段），
   **不要**为守护起 PowerShell 子进程；`psutil.net_if_addrs()` 只有名字，不够。
2. 描述命中隧道词汇（`tunnel|tap|wintun|meta|vpn|dummy|bridge|vmnet`）→ 该适配器地址不作候选；
   命中不了就**不**据此放行，仍走现有 DNS 应答校验（`lan_probe_address`）作为第一道。
3. `"28."` 前缀**暂时保留**，直到 1-2 的用例与本机实测都通过再摘——摘早了就是回归。
4. 用例：a) 描述含 "Meta Tunnel" 的适配器上的 28.0.0.1 必须落选；
   b) 描述含 "Wireless LAN" 且地址是 28.1.2.3 的候选必须入选（这条正是 E22 那所假想学校）；
   c) 拿不到适配器描述（API 失败）时行为等于现状，绝不因此选中隧道源。

## 13. UI：设计方向与可访问性（intentional-design Review mode 结论）

### 13.1 现有方向复述（它是有方向的 UI，不是模板 UI）

1. **受众与场景**：用户本人，Windows 桌面小窗（420×680），掉线时焦虑地看一眼，一天看几次。
2. **目的**：一眼回答"通不通、要不要我动手"。
3. **性格**：工业仪表 / 石墨暗色 / balanced→偏 dense；刻意**不是**消费类 app 的亮色大圆角。
4. **布局**：单列堆叠 + 顶部状态仪表（答案在最上）。
5. **字体**：YaHei UI 主 + Consolas 遥测数字（第二族有理由：数字对齐；这条是对"单族"默认的破例）。
6. **颜色**：`theme.py` 集中定义——BG `#14161a`、PANEL `#1d2026`、EDGE `#2a2e36`、FG `#e8eaed`、
   FG_DIM `#8b919b` + 4 个降饱和语义色；语义色与托盘同源，**且有测试拦截漂移**。中性灰阶 +
   语义色，无品牌强调色（破例理由：本产品不需要营销式 CTA）。
7. **交互与无障碍**：**这一层是当前最大的洞**，见 13.2。

### 13.2 绝对违规（数字全部实测，非目测）

| 元素 | 违反项 | 实测 | 最小修法 |
|---|---|---|---|
| 控件边界 `EDGE/BG`、输入框 `PANEL/BG` | 控制边界对比 ≥3:1 | **1.33:1**（要求 3:1）——控件轮廓现在基本靠猜 | 新增 `BOUNDARY` token ≥3:1（约 `#6a7280` 一档），输入框"底 + 1px 真边"分离 |
| 所有按钮/输入框 | 焦点必须可见 | `highlightcolor`/`FocusIn`/`takefocus` **0 处**（grep 证实） | 统一 2px 焦点环；把 `highlightthickness` 从静态边框职责里解放 |
| 所有按钮 | hover/focus/disabled/loading 齐备 | 仅按下态 `activebackground`；**「自动检测」连 disabled 都没有** → 探测中可重复点击起多个后台线程，后到的提示覆盖先到的 | `bind <Enter>/<Leave>`；后台任务期间 disable + 文案"探测中…" |
| 日志窗 ERROR 行 | 正文 ≥4.5:1 | `#d05f52`/`#1d2026` = **4.23:1 FAIL**（22pt 状态大字 PASS） | 正文用红提到 `#e0705f` 一档；大字保留现值 |
| 键盘 | 主要动作可键盘完成 | 8 按钮 14 字段，**无 `<Return>`/`<Escape>`** | 服务器行回车=保存并测试；Esc 关高级窗 |
| 托盘 | 颜色不得是唯一载体 | tooltip 有文字（`keeper.py:1590`）是缓解，但扫一眼只有颜色 | 形状区分（实心/环/环+斜杠），`ellipse/polygon` 即可——**与裁 `_imagingft` 不冲突** |
| 触摸目标 | ≥44px | 现约 26-28px（`pady=4`+10pt）；桌面可辩护，**安卓不可** | token 定义 `control-h: 44px` 供 web 面板；Tkinter 桌面留 32px |
| 首帧 | 空/加载态要有设计 | 状态卡初始为 `—`，无解释 | 打开即"正在读取守护状态…"，`v6 未知` 三态各配文案 |

### 13.3 条件性违规（写理由，不顺手全改）

- **一屏无主次**：8 个等权按钮 + 表单常驻，但用户 99% 只要答案 → 状态优先、表单折叠（首屏 420×~300）；
  这条**同时**是"手机放不下 8 组字段"的前置，不是附加美化。
- **状态卡整圈语义色描边**（`app.py:379`）：最吵的元素是边框而不是答案 → 边框中性，
  状态由灯 + 字色承载，或只留左侧 2-3px 色条。
- **`PROBE_INTERVAL 3s`**：config key 名泄漏进 UI、中英混排、遥测条只承载一个字段 →
  中文化并让它承载真正会动的事（探测周期 / 退避倒计时 / 双栈状态）。
- **高级设置窗没有保存按钮**，靠"改完点主面板的『保存设置』"一句话打补丁（`app.py:160`）——
  跨窗注意中心是设计缺陷的自白 → 窗内自带保存/取消。
- **保留项**：底部"只自动登录本人账号，不绕过任何计费限制"——产品边界放在主屏，
  是"证明有人在意的细节"，不动。

### 13.4 落地分层（避免同一套 IA 做两遍）

- **今天（第一批，Tkinter）**：只修绝对违规——token 边界/焦点环/hover/回车/日志红/自动检测 disabled，
  约 40 行；对比度与焦点用脚本量出来，不靠眼看。**顺序排在 §3.1 三项之后、同批发布**：
  它不紧急，但绝对标准不可谈判，且与协议改动零交集（纯 UI 层），不增加回归风险。
- **只在 web 面板做一次**：13.3 的信息架构重排、`tokens.css`、`prefers-reduced-motion`、
  44px 目标、`ui_lint.py` 进 CI。**Tkinter 不做 IA 重排**（否则同套 IA 实现两遍，违背选型初衷）。
