# 版本路线（第一性原理重排，2026-11-24）

> 触发：v2.4.0-go 过夜核对（§7）实测显示 bind 修复「部分有效、未消除后半夜
> 4 小时长断窗」，促使从第一性原理重排优先级。本文是**版本级决策**，
> 单项技术决策仍在 `2026-11-23-v2.4.1-v4-multisource-decisions.md`。

## 0. 第一性原理：这个产品到底在解决什么

门户按**源 IP** 记会话 → 「我是谁 = 我从哪个 IP 出去」。所有已知 bug 都是这条的推论：

| 现象 | 同一条根因 |
|---|---|
| 双网卡浏览器旧账号/面板新账号 | 两个源 = 两个会话 |
| Doze 后 `bind: cannot assign`，4 小时不恢复 | wlan0 IP 从系统层消失，socket 绑不上 |
| 切账号要「全源」 | 每个源都要原子搬移 |
| v6 隐私临时地址仍归旧账号 | 每个地址是独立会话 |

由此，守护的核心价值不是「能登录」，而是**「掉了能自己爬起来」**。
§7 实测证明后者没做到：簇1（40 分钟恢复）✓，簇2（4 小时长断窗）✗。

## 1. 优先级重排（用户 2026-11-24 拍板）

**新顺序：源失效自愈 > v4 全源搬移 > 配置导入**

| 类 | 项 | 性质 | 版本 |
|---|---|---|---|
| **B · 源失效自愈** | ③ 注入 IP 自愈 + §7 新发现的 bind 4 小时不收敛 | **可用性**（产品存在的理由）；两端同源，合并排查 | **v2.4.1（第一优先）** |
| A · 归属正确性 | ① v4 全源搬移 + ② extra v6 补绑 | 正确性；双网卡环境现成可复测 | v2.4.1（B 之后） |
| C · 可维护性 | ④ 配置导入 | 换机/重装首配 | v2.5.0 |
| 安卓验收补全 | A4 完整版（FlClash/VPN 共存）、A5 IPv6 轮换 | 上次验收明确未做 | v2.5.0 |

### D-12 B 类合并 = 注入 IP 自愈与 bind 长断窗同源
- 决策：把 ③（安卓注入源过期）与 §7 新发现（PC/安卓共有的 `bind` 4 小时不收敛）
  合并为「源失效恢复」一个课题，统一查 `chooseRoute` 重选为何在「网卡 IP 从 ROM
  层消失」时不收敛、以及源变化后如何让守护 1 拍内恢复。
- 理由：用户拍板「重排，自愈优先」；第一性原理显示两者都是「源 IP 变了/没了，
  但重选没跟上」，分头修会重复造传感器（已有 `Client.Bindable`）。
- 被否：保持交接原顺序 ①②③④（那是按"发现顺序"排，不是按"用户价值"排）。
- 验证点：① 真机换 WiFi/路由器重启后 1 拍内恢复；② 过夜轮 bind 长断窗从
  4 小时收敛到分钟级——两项都要有实测数字。

## 2. 通用性双轨（用户 2026-11-24 拍板「两者都要」）

不复盘就 reopen 旧决策是不负责任的。核对事实：
- 11-12 用户拍板「诚实收敛、异校不立项、通用性增进空间=0」；
- 但协议层已在 `3a9d206` 通用化过（"能读懂的协议形状"扩展），且已有
  `2026-11-11-异校通用性调研.md` + `corpus-异校响应语料.md` 两份地基。

**双轨定义（与旧决策兼容，不推翻「异校不立项」）**：

| 轨 | 内容 | 与旧决策关系 |
|---|---|---|
| 轨1 · 跨环境鲁棒性 | 多网卡/多设备/网络切换/系统差异下都正确（= B 类 + A 类） | 不冲突，本来就在做 |
| 轨2 · 异校**调研**（非适配） | 只做调研文档明确的缺口 #1/#2：`cnal detect --fingerprint` 输出脱敏指纹（Server 头 / title / Location query / ac_id 等），生成配置草稿供人确认；建 `fingerprints/` 收样本 | 「不实现登录适配、不宣称支持第二所学校」——沿用旧决策的诚实边界 |

### D-13 异校轨只做「识别原料」，不做登录适配
- 决策：轨2 严格限定为调研文档 §4 缺口 #1/#2（保留 Location queryString + 脱敏指纹
  输出），不碰登录链路、不做动态 DSL、不加 Srun provider。
- 理由：用户要「小规模调研异校协议差异，只调研不实现」；调研文档 §6 明确
  「不宣称已支持任何第二所学校」，与此一致。
- 被否：适配更多学校门户（推翻 11-12 决策，无法验证）；完全不调研（用户否）。
- 边界：真要支持 Srun 得单独写 Go provider（`internal/protocol`），不在本轮范围。
- 验证点：`cnal detect --fingerprint` 输出经脱敏（IP/MAC/账号打码）；样本可贴 issue，
  但不生成"可直接登录"的配置。

## 3. 版本计划

- **v2.4.1**：B 类（源失效自愈，含 §7 新发现）→ ① v4 全源搬移；② 并入排查。
  每项走 实现 → trouble-maker → tester → 真机复测。
- **v2.5.0**：④ 配置导入 + A4/A5 补全 + 轨2 异校调研工具（`detect --fingerprint`）。
- **异校登录适配**：保持不立项（除非用户明确改主意）。

## 4. 一条工程纪律

per AGENTS.md「commit 前测试全绿」+ prove-it「交差自证」：
每个版本收尾必须 `cd go-cnal && go test ./... -count=1` 全绿并贴原样输出；
涉及界面的改动附浏览器/真机截图；bind 自愈必须有真机过夜数字才算验证。
