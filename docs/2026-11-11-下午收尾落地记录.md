## 2. 首跑探测：Host 白名单（端到端 `cnal detect` 跑通的关键）

故障：`cnal detect` 未认证态下恒失败。逐锚点诊断文本（`未探测到校园门户。逐锚点实测：…`）
定位到——本校把**强制门户探测域名放行**了：

| 未认证态请求 | 应答 |
|---|---|
| `http://223.5.5.5/generate_204`（不带 Host） | 302 → `https://a.stu.edu.cn:443/ac_portal/proxy.html?...`（劫持，能看到门户） |
| 同上 + `Host: connect.rom.miui.com` | **真 404**（被白名单放行，看不到劫持） |
| 同上 + `Host: www.msftconnecttest.com` | 真 200 |
| 同上 + `Host: www.example.com` | 302 → 门户 |

`connect.rom.miui.com` 是 `defaultProbeHost`，而我们把 Host 焊死在它上面 → 探测在未
认证时也拿到真应答、永远看不到 302。修法（`probeHostVariants`）：**先不带 Host 探一次，
再带配置 Host 探一次**（有些校园反过来按域名劫持，配置值仍保留为第二次尝试）。

- 端到端结果（真机）：`cnal detect` → `门户: https://a.stu.edu.cn:443`；
- 单测 `TestProbeHostVariantsTriesWithoutHostFirst`（先空 Host、再配置值、空白视同未配）；
- 每次探测都 `diag` 累积「逐锚点实测」结论，首跑失败时用户看得见卡在哪一环。

## 3. 会话判死：权威信号一拍判死（主文 §11.3 收紧，见主文注）

## 4. 安卓 M1：A4 绑网正确性（真机 3/3 PASS）

A4 通过线：门户侧看到的出口 IP == 绑定的 Wi-Fi 地址，且必须证 **Go native socket**
那条路（Android 文档只承诺 Java 层 `bindProcessToNetwork`，M1 登录走 Go 的
`net.Dialer.LocalAddr`，得实测）。

- `mobile.EgressCheck(loginURL, insecure)`：用注入的物理源打门户无凭据查询，
  `insecure` = `ssl_verify` 取反（安卓系统信任库 149 个 CA 里没有本校 `Xcc Trust OV SSL`，
  同证书 Windows 能过、Android `CertPathValidatorException`——跳过 CA 链但仍校主机名）；
- Kotlin `A4Egress`：单引号字典解析（门户回 `{'ip':'…'}`，**不是 JSON**，别换回 JSONObject）；
- `ProbeLog.a4` 单行定序日志，`A4 .* verdict=PASS` 可统计通过率；
- 判定**只看 Go 路**：Kotlin 控制路走明文 HTTP 会被本 app 的
  `network_security_config` 拦下（`Cleartext HTTP traffic not permitted`），那是自家策略生效，
  不算 A4 失败。

真机结果（Xiaomi 13，USB 调试安装）：**3/3 `verdict=PASS`**，`go=172.29.153.170`、
`wifi=172.29.153.170`。→ Go socket 在绑网下确实走 Wi-Fi，M1 登录路径的出口正确性成立。
