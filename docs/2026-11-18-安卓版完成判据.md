> 起因：用户问「什么时候能算安卓版做好了？还能保证最初需求吗？通用、实用、轻量」。
> 用 grill-me 逐支走完设计树（5 问），把三个形容词变成可验收的判据，而不是口头承诺。

## 三条判据（用户接受）

### 实用 = 四种真实场景都不添乱

| 场景 | 判据 | 证据 |
|---|---|---|
| 开梯子（VPN） | VPN 开→守护暂停自动登录（探测/展示照常），关→立即恢复+通知 | A4 A/B 实测（Go socket 被 TUN 抓走）+ VpnGuard 降级解真机边沿验证 |
| Wi-Fi↔蜂窝切换 | 事件路径 ≤5s 内重探测，不误登录 | A1 事件路径已验 |
| 免流/免认证时段 | 自动学习免会话态，整夜零登录 | A3 整夜 0 次自动登录实证 |
| 踢线恢复 | ≤5min（门户静默）/亮屏 1 拍内 | A1 踢线轮 113s 过 |

### 轻量 = 资源有实测数字、不引新依赖

- 息屏电耗 ≤3%/h：**实测 0.65%/h**（A2+A3 合并轮，余量 4.6×）
- 常驻内存 <60MB：待本轮真机收表核实（当前 FGS 运行时读数）
- 不引新依赖：VPN 暂停只加一个纯函数（VpnGuard）+ 复用 NetworkCallback /config 缝，零新库

### 通用 = 同一内核零改动跑三种壳，场景适配只在 Kotlin 边界层

- 内核（keeper/protocol/dialect/netstack/api）不因场景新增代码
- 场景适配各一个系统 API 判据：VPN=TRANSPORT_VPN、Wi-Fi=TRANSPORT_WIFI、免流=锚点绿+登录不受理
- **不猜特定 App、不逐校适配**（README 已拍板不立项异校通用，实测 0 所异校）

## 完成定义

**VPN 暂停自动化做完 + 真机边沿验证过 = 安卓版宣布完成**。不做：异校自助适配（未验证目标）、v6 主动 rebind（门户已自动恢复会话，不存在的问题）。
