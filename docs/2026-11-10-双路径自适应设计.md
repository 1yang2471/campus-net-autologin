# 双路径自适应：让守护在有/无 TUN 代理的环境下都能自动登录

> 2026-11-10。起因：启用以太网后 v6 断、v4 不自动连、手动重连无效
> （根因见 `2026-11-10-以太网启用后守护失效诊断.md`）。目标一句话：
> **插不插网线、开不开代理，守护都能自动登录，用户上网不受影响。**
>
> 本文是**设计文档**（grill-me 逐项确认后成稿）；第一期已落地（见 §12），
> 第二期未做。
>
> **⚠ 2026-11-11：第二期按 `2026-11-11-根因修正与门户选源设计.md` 修订**——
> 11-10 的「DNS 劫持」根因被真机否证（`1.1.1.2` 就是门户），第二期要解决的是
> **「选哪个物理源」**（门户可达性探测），而不是「换哪条栈」。

## 0. 结论（一句话）

守护目前只有一条硬编码路径：**绑物理源 + 钉门户真实 IP + 直连**。在
FlClash 这类 TUN 代理环境下（`dns-hijack: any:53` + 全量默认路由），这条
路**拿不到门户真实 IP**，必然失败。

改为**双路径自适应**：同一份内核，按"逐操作健康探测"在
「绑物理源」与「系统栈（跟 TUN 走）」之间自动选路；两条都能用时**绑源优先**；
两者状态**分别上报**，不一致就在面板提示。默认全自动，另留手动强制开关。

## 1. 目标与非目标

**目标**
- 插/拔网线、FlClash 开关，守护都能自动登录，不用手动干预。
- 有线优先，拔了无缝回 WLAN（由系统路由 metric 自动完成，守护不抢方向盘）。
- 通用性第一：不假定用户一定用 FlClash、也不假定一定不用代理。

**非目标（本轮不做）**
- 不改 FlClash 配置（用户要 FlClash 常开，且要求方案通用，不能依赖某份订阅规则）。
- 不做网卡变化事件监听（Windows-only，本轮先用"探测失败即重探"达到近似效果）。
- 不做多设备互踢、不做 v6 临时地址轮换收敛（那是 A5/V1-V3 范畴）。

## 2. 实测事实（判据先量；含两处自我否证）

| 事实 | 证据 |
|---|---|
| FlClash TUN 全量接管 | `tun.enable=true`、`stack=gvisor`、`dns-hijack=["any:53"]`、装了 `0.0.0.0/0 → 28.0.0.2` 默认路由 |
| 系统 DNS 被 fake-ip 化 | `a.stu.edu.cn → 28.0.0.136`（fake-ip `28.0.0.1/8`） |
| **绑源也拿不到真实 IP** | 原始 UDP 直接问校园 DNS `10.129.17.10`：不绑源→`28.0.0.136`，绑 WLAN/ETH→`1.1.1.2` |
| 门户是内网专用域名 | 公网 DoH 查 `a.stu.edu.cn` → **NXDOMAIN** |
| 经系统栈可达门户 | `curl https://a.stu.edu.cn/...` → HTTP 200、15595B、含"登录" |
| 出口 IP 不因代理改变 | 直连与经 `127.0.0.1:7890` 出口都是 `218.16.203.46`（因规则 `DOMAIN-SUFFIX,CN,DIRECT`）|
| v6 物理链路是好的 | `ping -6 -S <WLAN GUA>` 通（0% 丢包）；TCP 绑源连 Ali v6 443 成功 |
| v6 默认路由被抢 | `::/0` → FlClash `fdfe:...::2` metric 0，WLAN metric 256 |

**两处自我否证（保留，提醒后来者别重犯）**
1. ❌ "v4 绑源不通"——**错**。当时连的是 fake-ip `28.0.0.136`，而 fake-ip
   只在 TUN 内有效，绑物理源连它必然超时。重测绑源连字面公网 IP
   （`223.5.5.5:80`）→ **三个源全通**。绑源的路本身没问题。
2. ❌ "问题在路由/绑定"——**不准确**。真正卡死的只有**域名解析**：
   绑源直接问校园 DNS 也被 `any:53` 劫持。

## 3. 双路径定义

| | 路径 A：物理栈 | 路径 B：系统栈 |
|---|---|---|
| 做法 | 绑物理源 + 钉门户真实 IP（现状） | 不绑源、不钉 IP，域名交给系统/代理（与浏览器同路） |
| 适用 | 无 TUN、或 TUN 未接管 DNS/路由 | TUN 接管（`dns-hijack:any:53` / 全量默认路由） |
| 优点 | 读数=校园网真实态；凭据不经代理 | 与用户实际上网同路；抗拓扑变化 |
| 风险 | TUN 下拿不到真实 IP → 失败 | 若代理把校园域名判为代理，凭据经境外节点 |

**绑源优先**：两条都健康时优先 A（安全 + 可观测）；A 不可用才用 B。

## 4. 逐操作健康探测（核心机制）

不是"整机选一条路"，而是**每类操作各自探测**：

| 操作 | 走法 | 理由 |
|---|---|---|
| L1 锚点探测（字面 IP，如 `223.5.5.5`） | **始终绑源** | 不需要 DNS，绑源可通；读数保留"校园网真实态" |
| 门户解析 / 登录 / 补绑 / flux | **先绑源解析，失败转系统栈** | 需要域名解析，TUN 下绑源必失败 |
| v6 探针 / 握手 | **各自健康探测** | v6 绑源可直连、系统栈也通，分开判 |

探测结果**逐操作缓存**，失败即重探（替代 30s 节流），恢复目标 ~1-2s。

## 5. 在线语义（分别报，不一致就提示）

- 绑源探针（校园网真实态）与系统栈探针（用户实际路径）**分别记录**。
- 面板同时展示两条状态；**不一致时明确提示**（例如"校园网在线，但代理路径异常"），
  不互相掩盖。
- 状态快照新增字段承载第二路径读数（沿用现有 `Snapshot.Extra` 扩展位思路）。

## 6. 配置面

- `net_mode = auto | bound | system`，默认 `auto`。
  - `auto`：逐操作健康探测（本文行为）。
  - `bound` / `system`：手动强制走某条路（自动判错时的逃生口，沿用 `bind_ip` 的思路）。
- 面板可视化：显示当前走哪条路、两条探针各自状态、提供"手动重探"入口。
- `bind_ip` 语义不变（手工钉 v4 源，仅在 `bound`/`auto` 的 A 路径生效）。

## 8. 落地节奏（分两期）

**第一期（最小可用，先让网通）**
1. `netstack.Client` 加"不绑源"通道；
2. `deliverPinned` / 门户解析加"绑源失败 → 系统栈"回退；
3. `net_mode` 配置（先支持 `auto`，`bound`/`system` 手动值）；
4. 日志明确说出"这一拍走了哪条路、为什么"。

**第二期（健壮性与可观测）**
5. L1/L2/v6 逐操作分路 + 双路径读数；
6. 适配器描述识别 TUN（`GetAdaptersAddresses`，规格 §11.6 v3 已备方案）作快速定档；
7. 探测失败即重探（替代 30s 节流）；
8. 面板双状态可视化 + 手动重探。

## 9. 验证

- 单测：新分支用假 DNS/假拨号覆盖（不联网），守"绑源优先、失败回退、模式强制"。
- **真账号登录实测（用户执行，唯一能证明"经系统栈登录真能建立会话"的办法）**：
  1. FlClash 开 + 网线插 → 应自动上线；
  2. 拔网线 → 应回 WLAN 上线；
  3. FlClash 关 → 应走绑源路径上线；
  4. 每种拓扑记录：走了哪条路、多久恢复、面板两路状态。

## 10. 未决 / 需真机确认

- **经系统栈提交登录能否真建立会话**——HTTP 200 只证明可达，未证明认证成功。
  这是本方案最大未验证点，只能靠真账号实测（§9）。
- 适配器描述 API（`GetAdaptersAddresses`）在本机的可靠性——规格 §11.6 记了
  `winreg` 联表返回空的坑，落地时必须 fail-closed。
- v4/v6 分探的具体判据（探什么目标、超时多少）——第二期细化。
